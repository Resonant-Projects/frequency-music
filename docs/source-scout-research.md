# Source Scout research discovery and page capture

Source Scout searches against graph gaps, judges candidates, then writes canonical Sources in Convex. The general-web channel is Firecrawl; OpenAlex and Europe PMC add paper-focused discovery without account signup. Results are interleaved under the existing per-query cap so Firecrawl cannot crowd out scholarly records, with DOI/URL dedupe and per-provider audit outcomes. Search hits are candidates, not evidence of a paper's claims. DOI and publication metadata supplied by a search index remain unverified until checked against the publisher or registry. Exa (possibly the requested “Expo”) was evaluated as an optional publication search with a free-credit tier, but not integrated because it needs a separate account/key and these keyless scholarly providers cover the first release; Tavily is a web-search alternative, not an authoritative paper index.

For judged Source candidates, the agent worker may fetch public HTML through Keith's self-hosted Crawl4AI server. The agent-tool `ingestScoutedSource` stores at most 30,000 characters as `rawText` with `metadata.scoutedBy.contentProvider = "crawl4ai"`; the canonical dedupe mutation never overwrites an existing Source. Successful content enters `text_ready`, eligible for the existing batch Extraction workflow. A failed crawl still records the URL-only Source and does not falsely mark it ready. PDF URLs are not sent to the HTML crawler; PDF/OCR needs a separate intake path. Feed proposals remain disabled until human approval.

## Activation

The agent worker needs `CRAWL4AI_API_TOKEN` in its runtime environment and network access to `https://crawl4ai.rproj.art`. Crawling is disabled by default even with a token: the worker requires `CRAWL4AI_EGRESS_GUARDED=true` after an operator verifies the Crawl4AI deployment enforces private/reserved address blocking at network egress, including DNS resolution, redirects, and cloud metadata targets. The client's initial-host check is not an SSRF boundary. Until that deployment protection exists, leave this flag false and the Scout will ingest URL-only Sources. The 1Password reference is in `agent/.env.schema` (`Homelab Runtime` vault); the schema documents the contract but the worker does not automatically load Varlock. Supply the token through the worker's existing secret delivery, not source control, a command argument, or a chat message. `CRAWL4AI_URL` optionally overrides the default server URL. Firecrawl still uses `FIRECRAWL_API_KEY`. OpenAlex and Europe PMC require no keys; the former has a small anonymous daily search budget, so the Scout caps calls and should be observed for 429s.

Do not run `convex dev`, `run`, `codegen`, or `deploy` just to test this: the repository has one live self-hosted deployment. Unit tests run with recorded/mocked responses. Before activating the worker, verify its secret binding, server reachability from that worker, and deployment preview. After deployment, inspect the agent audit trail and confirm an actual scouted Source has `text_ready`, nonempty `rawText`, and eventually an Extraction with Claims; none of those states follows from a green unit test alone.

First-party references: https://docs.crawl4ai.com/core/self-hosting/ ; https://help.openalex.org/api/ ; https://europepmc.org/RestfulWebService .
