# Source Scout research discovery and page capture

Source Scout searches against graph gaps, judges candidates, then writes canonical Sources in Convex. The general-web channel is Firecrawl; OpenAlex and Europe PMC add paper-focused discovery without account signup. Results are interleaved under the existing per-query cap so Firecrawl cannot crowd out scholarly records, with DOI/URL dedupe and per-provider audit outcomes. Search hits are candidates, not evidence of a paper's claims. DOI and publication metadata supplied by a search index remain unverified until checked against the publisher or registry. Exa (possibly the requested “Expo”) was evaluated as an optional publication search with a free-credit tier, but not integrated because it needs a separate account/key and these keyless scholarly providers cover the first release; Tavily is a web-search alternative, not an authoritative paper index.

For judged Source candidates, the agent worker may fetch public HTML through Keith's self-hosted Crawl4AI server. The agent-tool `ingestScoutedSource` stores at most 30,000 characters as `rawText` with `metadata.scoutedBy.contentProvider = "crawl4ai"`; the canonical dedupe mutation never overwrites an existing Source, with one exception: a Source the Scout itself created URL-only (still `ingested`, no text) may gain captured text on a later run, recorded as `metadata.scoutedBy.contentProvider` and `capturedByAgentRunId`. Successful content enters `text_ready`, eligible for the existing batch Extraction workflow. Only the source-scout ingest node supplies `rawText` and `contentProvider`. Both are kept out of the LangChain tool schema, and the mutation rejects captured text from any run whose graph is not `source-scout`, so a model cannot assert Crawl4AI provenance. A failed crawl still records the URL-only Source and does not falsely mark it ready. Before crawling, the Scout asks `findExistingSourceUrls` which candidates already own the same canonical URL dedupe key and whether each still awaits capture. Known Sources with text, or from other intake paths, skip page capture because duplicate intake would discard the text. A scout URL-only Source is crawled again, so it recovers after a crawler outage. The Scout emits canonical URLs (DOI lowercased, tracking parameters removed, query sorted), and the preflight also checks the provider's original spelling. When a Source already exists under that spelling, from another intake path, the Scout ingests the original so canonical dedupe matches it. Crawl requests exclude images, and the worker refuses crawl responses larger than 16 MB before parsing. If that preflight fails, the Scout crawls as before and intake still dedupes. Scholarly search keeps a provider's full publication date only; a year-only record carries no `publishedAt`. PDF URLs are not sent to the HTML crawler; PDF/OCR needs a separate intake path. Feed proposals remain disabled until human approval.

## Activation

The agent worker needs `CRAWL4AI_API_TOKEN` in its runtime environment and network access to `https://crawl4ai.rproj.art`. Crawling is disabled by default even with a token: the worker requires `CRAWL4AI_EGRESS_GUARDED=true` after an operator verifies the Crawl4AI deployment enforces private/reserved address blocking at network egress, including DNS resolution, redirects, and cloud metadata targets. The client's initial-host check is not an SSRF boundary. Until that deployment protection exists, leave this flag false and the Scout will ingest URL-only Sources.

Egress verification, 2026-09-29, Crawl4AI 0.9.4 at `crawl4ai.rproj.art`: the 0.9 Docker server validates destinations after DNS resolution and routes Chromium through its pinning egress proxy. `POST /crawl` returned HTTP 400 `URL blocked (SSRF protection)` for `169.254.169.254`, `127.0.0.1`, `[::1]`, `[::ffff:127.0.0.1]`, `0.0.0.0`, decimal and octal loopback forms, `172.16.10.13`, `100.64.0.1`, a Tailscale hostname, and public DNS names that resolve to private addresses (`127.0.0.1.nip.io`, `10-0-0-1.sslip.io`). A public URL that 302-redirects to loopback or the metadata address returned `success: false` with the proxy's `URL blocked` body, which the client discards. A public page crawled normally. That evidence satisfies the gate above for this deployment. Page text now has a fallback and a bot-wall filter (2026-09-30). The first Scout run after activation stored two JSTOR "verifying your browser" pages as `text_ready`, and Crawl4AI never attempts PDFs. A shared `looksLikeBotChallenge` check (`convex/shared/agentContract.ts`) now drops short browser-check and bot-wall text in the worker and refuses it at `ingestScoutedSource`. When Crawl4AI yields nothing usable, and always for PDFs, the worker scrapes the Lab's self-hosted Firecrawl (`FIRECRAWL_API_URL`, never Firecrawl Cloud) and records `contentProvider: "firecrawl"`. That path is gated by `FIRECRAWL_SCRAPE_EGRESS_GUARDED=true`: on 2026-09-30 the Lab Firecrawl's `/v2/scrape` returned no content for the metadata address, loopback (including `nip.io` and decimal forms), `0.0.0.0`, the NPM address, the Convex backend port, CGNAT, and public redirects to loopback and metadata, while `example.com` succeeded. Firecrawl could not pass the JSTOR or DataDome walls either, but it parsed the mtosmt PDF that Crawl4AI skipped. `sources:resetScoutCapture` clears a bad capture so a later run can capture the Source again. When neither crawler can pass a bot wall, the worker asks OpenAlex for the work's abstract (`contentProvider: "openalex"`). It looks up the DOI the URL names first: a `doi.org` link, a publisher `/doi/` path, or a JSTOR stable page, whose DOI is `10.2307/<stable id>`. Otherwise it uses the search hit's title, accepting only an exact, unambiguous match of at least four words. The stored text begins `Abstract from OpenAlex (<work id>; DOI …). The full text was not captured.` so Extraction knows it is an abstract. On 2026-09-30 both walled JSTOR candidates resolved this way (one by DOI, one by title to its Project MUSE record), and the DataDome-walled ResearchGate page, which OpenAlex does not index, stayed URL-only. FlareSolverr was evaluated and rejected: it passed JSTOR's browser check but returned only citation metadata, failed on DataDome, and fetched internal LAN addresses. Re-verified 2026-09-30 after CT 109 gained a persistent JWT signing key (homelab-infra #585), using the worker's own token: the same private, loopback, metadata, NPM, IPv6 and private-resolving DNS targets returned HTTP 400 `URL blocked`. The public-redirect probes to loopback and the metadata address now report `success: false` at the 302, with Crawl4AI's anti-bot message instead of the proxy's `URL blocked` body; no internal content is returned either way. Because those probes stop before the redirect is followed, they did not re-exercise redirect handling. Redirect protection still rests on the 2026-09-29 result, which stands because #585 changed only the JWT signing key, not the Crawl4AI version or its egress settings. The next re-run needs a public redirect that Crawl4AI follows. Re-run the same probes after any Crawl4AI upgrade or configuration change, and keep `CRAWL4AI_ALLOW_INTERNAL_URLS` unset on the server, because that escape hatch disables the protection. The 1Password reference is in `agent/.env.schema` (`Homelab Runtime` vault); the schema documents the contract but the worker does not automatically load Varlock. Supply the token through the worker's existing secret delivery, not source control, a command argument, or a chat message. In production the Kubernetes worker receives a `data` scope client JWT (1Password `Crawl4AI Frequency Worker Token`, never the server's admin token) through its ExternalSecret, with `CRAWL4AI_URL=http://172.16.10.19:11235` and `CRAWL4AI_EGRESS_GUARDED=true` (homelab-infra #586, #589); renewal and revocation are documented in homelab-infra `services/crawl4ai/README.md`. `CRAWL4AI_URL` optionally overrides the default server URL. Firecrawl search uses `FIRECRAWL_API_URL` when set, for example the Lab's self-hosted `http://172.16.10.38:3002`, and sends it no credential. Unset or empty means Firecrawl Cloud, which needs `FIRECRAWL_API_KEY`; that key is sent only to `https://api.firecrawl.dev`. Europe PMC requires no key. OpenAlex works without one, but keyless calls share a small daily budget per egress IP. On 2026-10-01 a day of Scout runs plus operator lookups spent it. From then until midnight UTC, the worker's OpenAlex search and abstract fallback returned HTTP 429, and the Scout fell back to its other providers. `OPENALEX_API_KEY` (a free key from openalex.org, 1Password `Homelab Runtime/OpenAlex API Key`) gives the worker its own budget. Both OpenAlex call sites send it as an `Authorization: Bearer` header, so it never appears in a URL or a logged error.

Do not run `convex dev`, `run`, `codegen`, or `deploy` just to test this: the repository has one live self-hosted deployment. Unit tests run with recorded/mocked responses. Before activating the worker, verify its secret binding, server reachability from that worker, and deployment preview. After deployment, inspect the agent audit trail and confirm an actual scouted Source has `text_ready`, nonempty `rawText`, and eventually an Extraction with Claims; none of those states follows from a green unit test alone.
