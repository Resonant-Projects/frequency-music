# Local embeddings for Convex ingest

**26 November 2026.** An RTX 5090 makes self-hosted text embeddings feasible. Start with **Qwen3-Embedding-4B** and compare the lighter 0.6B model against Frequency’s existing OpenAI baselines. The [evaluation plan](../plans/2026-11-26-local-embedding-evaluation.md) defines the passage comparison, and the [migration plan](../plans/2026-11-26-local-embedding-migration.md) covers the later cutover. Hosted embedding calls can be retired once index and query paths migrate. Source capture and Anthropic extraction are separate stages. ## Serving and index compatibility

- The 5090 has 32 GB of VRAM and CUDA compute capability 12.0. Nominal BF16 weights are roughly 1.2, 8, and 16 GB for Qwen’s three sizes, before activations, batches, and runtime overhead. Start with BF16 on a pinned CUDA/PyTorch build with Blackwell support and a context cap based on measured input lengths. PyTorch introduced Blackwell support with its CUDA 12.8 wheels. [NVIDIA 5090 specifications](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5090/) · [CUDA GPU table](https://developer.nvidia.com/cuda/gpus) · [PyTorch release](https://pytorch.org/blog/pytorch-2-7/)
- Serve Qwen on a private vLLM pooling endpoint using OpenAI-compatible `/v1/embeddings`. Verify batch ordering, finite vector values, output dimensions, and truncation behavior against a Sentence Transformers reference for the pinned model. Qwen supports shorter outputs via Matryoshka training. vLLM documents a model override when the default config fails to advertise that support. Perplexity documents TEI 1.9.2+ with INT8 output. Casting its values to Convex numeric vectors preserves their cosine comparison and gives up the compact INT8 storage. [vLLM embedding API](https://docs.vllm.ai/en/latest/models/pooling_models/embed/) · [Perplexity serving guide](https://huggingface.co/perplexity-ai/pplx-embed-v1-4b)
- The checkout uses OpenAI `text-embedding-3-small` at 1,536 dimensions for claims, concepts, and the separately metered hypothesis tournament. Source passages use `text-embedding-3-large` at 3,072 dimensions. The pinned Convex RAG component supports specific dimensions and excludes 2,560, so try Qwen 4B at 2,048 for passages and 1,536 for the small-model paths. Qwen 8B can produce 3,072. Every model change still needs fresh vectors from the original text in separate indexes or RAG namespaces while comparing and cutting over. Matching dimensions only preserves the vector shape. ## Evaluation before switching

- Use a fixed, labeled sample of papers, articles, and transcripts with exact tuning phrases, paraphrases, and near-topic distractors. Include the existing `432 Hz precise temperament tuning` case. Keep chunking and result limits fixed. Compare each model with its corresponding OpenAI baseline using Recall@k and nDCG@k. Run vector-only first to isolate the embedding change, then replay the actual hybrid ranking and check that the returned passage supports the query. [Passage acceptance evidence](../evidence/passage-search-repair-20261024.md) · [Hybrid search](../../convex/passageSearch.ts)
- Evaluate claim and concept neighbors separately. For hypothesis deduplication, label true paraphrases and related but distinct statements, then tune the cosine threshold on a development split and report false merges and missed duplicates on a held-out split. Measure warm p95 query latency, batch ingest throughput, and peak VRAM with search and ingest running together. Set the minimum quality and capacity targets against the baselines before choosing a model. [Tournament threshold](../../convex/shared/hypothesisTournament.ts)

## How to migrate

1. Start with passages. Confirm that the Convex action runtime can reach a private, authenticated GPU endpoint. Backfill from stored text into a new, separately named RAG namespace. RAG v0.7.8 allows one ready version per name, so a separate name lets both indexes serve comparison queries. Preserve hybrid ranking, source filters, provenance and deletion behavior, and verify that the local index covers current source hashes before switching both passage indexing and search to it. [Passage indexing](../../convex/passages.ts) · [Passage search](../../convex/passageSearch.ts) · [RAG namespace promotion](https://github.com/get-convex/rag/blob/v0.7.8/src/component/namespaces.ts)
2. Migrate claims, concepts and tournament embeddings after the passage trial. The tournament also searches stored hypotheses and archived candidate statements. Its neighbor hydration checks statement hashes on hypotheses and vector presence on candidates. It needs a model-aware cutover for both sets as well as calibration of the duplicate threshold. The metered embedding path also needs to keep supplying token counts for the tournament's run budget. [Tournament neighbor hydration](../../convex/hypothesisTournament.ts#L774) · [Tournament embedding client](../../convex/hypothesisTournamentNode.ts#L52)

Passage indexing is scheduled when source text is saved. Measure time from the source write to a searchable passage, plus query latency and GPU utilization. The October backfill had a roughly $1.48 estimated API cost and two sources hit Convex's write limit before a smaller rerun succeeded. Local serving offers control over where embedding text goes and removes provider quotas. Backfill still needs to respect Convex write capacity. PDF capture uses Lab Firecrawl, and extraction has its own Anthropic model policy. [Source write](../../convex/sources.ts#L348) · [October backfill results](../evidence/passage-index-20261017/acceptance.md#L235) · [PDF capture](../pdf-capture.md) · [Extraction model policy](../../convex/shared/llmPolicy.ts#L34)

This assessment used public documentation and the repository checkout. GPU capacity under load, network reachability from Convex, and retrieval quality on Frequency's corpus remain to be measured.
