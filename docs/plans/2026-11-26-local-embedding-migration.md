# Migrate Frequency Music embeddings to local inference

Use the model and configuration that pass the [passage evaluation](./2026-11-26-local-embedding-evaluation.md). Convex remains the owner of Source text, vectors and retrieval. This work covers embedding and semantic indexing. The [PDF capture path](../pdf-capture.md) and [structured extraction policy](../../convex/shared/llmPolicy.ts) are separate.

## Stage 1 — Move passage indexing and search together

1. In [passage indexing](../../convex/passages.ts), [passage search](../../convex/passageSearch.ts) and the [shared passage contract](../../convex/shared/passages.ts), make the namespace, provider model, dimension and query preparation one configuration. Keep the current configuration available for comparison and rollback. Give the local index a separate namespace name because the pinned RAG component permits one ready version per name. Use a private HTTPS endpoint from Convex and dedicated server credentials. Keep the existing source-text hash, source type, live status and provenance checks.
2. Reuse the [passage backfill](../../scripts/backfill-passages.ts), content-hash checks and sweep to build the local namespace in bounded batches while the current index serves search. Apply Source text changes and removals to both namespaces before checking coverage. Continue applying changes to both during the rollback window, and include hosted calls in the approved cutover budget. A canary must show that rerunning a batch skips current hashes and that edited, cleared and hard-deleted Sources converge. The prior [write-limit evidence](../evidence/passage-index-20261017/acceptance.md#stage-4-full-apply) calls for throttling based on Convex write capacity even when inference is faster.
3. Before either switch, pause and drain Source changes and passage jobs that affect the indexes. Reconcile the destination namespace, including failed work, against the current Source text hashes. Verify that every text-bearing Source has a current ready entry and only current ready entries contribute searchable chunks. Clean up abandoned pending and replaced entries with searchable chunks left by partial writes. Switch search and its matching embedding configuration only after these checks pass, then resume Source writes. If reconciliation fails, keep the current search route and resume writes. Outside the switch window, a provider outage must allow Source writes and leave incomplete indexing visible for backfill or sweep catch-up. In the isolated rehearsal, account for an edit before the forward switch and a hosted passage write interrupted between RAG chunk batches before rollback. Verify that the destination accepts only embeddings and queries with matching model, revision, dimension and input conventions.

## Stage 2 — Move claims, concepts and tournament statements

1. Evaluate claim and concept neighbors, cross-source correspondence candidates, tournament evidence retrieval and hypothesis duplicates separately against `text-embedding-3-small`. Fix the held-out relevance labels, duplicate paraphrases and distinct near-neighbors before comparing models. Require local Recall@k at or above the hosted baseline for each retrieval path at its production result limit, including the tournament's `searchEvidence` action with its existing candidate and evidence limits. For duplicates, replay the same labeled candidate statements against the same corpus through the tournament's bounded neighbor search and duplicate decision, with the same judge configuration. Require duplicate recall at or above baseline and false-positive rate at or below baseline on those end-to-end decisions. If any condition fails, keep the hosted configuration for Stage 2. Tune a local cosine threshold on development fixtures and keep the [existing hosted threshold](../../convex/shared/hypothesisTournament.ts) in the hosted configuration. Preserve the [tournament token-budget contract](../../convex/hypothesisTournamentNode.ts), including the input bound before a call and actual token usage on successful calls. Confirm the model and dimension against this evaluation even if the same GPU endpoint serves both stages.
2. Version the local space separately for claim and concept vectors and for stored hypothesis and candidate statement vectors. Use separate vector fields and indexes where old and local rankings must coexist. Reuse the [claim/concept backfill](../../scripts/embed-backfill.ts) and [hypothesis backfill action](../../convex/hypothesisTournamentNode.ts#L234) where they support backfilling the configured space. Include tournament archive rows, which currently lack a per-vector model label. Preserve the original statement text and record local vector provenance. Match every query to its own space before nearest-neighbor selection, including [correspondence candidates](../../convex/correspondenceCandidates.ts), probing, hypothesis neighbors, and tournament evidence search. A change in vector width is optional. Changing the model always requires re-embedding.
3. In isolated Convex, test mixed old and local data, backfill restart, updates during backfill, selector rollback, budget accounting, and old tournament candidates. At cutover, pause and drain writes affecting the indexed corpora, including in-flight tournament runs. Reconcile and verify local vectors against the current corpus after the drain. Switch the indexing and query paths and their duplicate threshold together before resuming writes. Preserve the hosted indexes until rollback verification ends. To roll back, pause and drain the same writes, reconcile the hosted vectors with the current corpus under an approved hosted budget, and verify coverage and text freshness. Restore hosted indexing, query routing and the hosted threshold together. Rehearse a candidate written during the forward drain and additions, edits and removals made after cutover. Confirm hosted duplicate decisions on the labeled pairs after rollback. Verify all application embedding paths can run with `OPENAI_API_KEY` absent before retiring the hosted embedding configuration. Audit operator scripts, env documentation and budgets for references to the retired provider. Confirm cleanup separately after the rollback window.
