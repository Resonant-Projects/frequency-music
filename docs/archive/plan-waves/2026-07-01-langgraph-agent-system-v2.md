- Audit-only write policy documented in `docs/agent-tool-surface.md`.

**LangSmith**

**Deployment substrate**

### Not yet implemented (verified gaps)

1. **Codex adapter targets the wrong protocol.** `agent/src/models/codexAppServer.ts` assumes an OpenAI-compatible `POST /v1/chat/completions` endpoint. `codex app-server` is JSON-RPC over stdio, not an HTTP completions server. The spike script has the same assumption and cannot succeed against a real Codex install. Replaced by the Codex SDK approach in plan `01`.
2. **Convex tracing is incomplete.** `convex/hypotheses.ts`, `convex/recipes.ts`, `convex/weeklyBriefs.ts` still call `generateText` untraced. Each needs the same node-runtime split `extract.ts` already has (only `extract.ts`, `tracing.ts`, `editorialExports.ts` are `"use node"` today).
3. **No golden datasets.** `data/eval/` does not exist; `upload-datasets.ts` and the experiment runners have nothing to run against. No `judge.ts` LLM-as-judge evaluator and no `eval-weekly-brief.ts` (both were tasks in `planning/langchain/2026-05-14-langsmith-integration.md`).
4. **Draft payloads are too thin to promote.** `agentReviewDrafts` stores title/summary/candidateIds only — not the structured fields (`whyThisMatters`, claims linkage, recipe parameters) required to promote a draft into a real `hypotheses` or `recipes` row. There are also no `approve`/`reject`/`promote` mutations for drafts (the status enum exists; nothing transitions it except creation).
5. **No pending-run polling surface.** `listPendingAgentRuns` / `getAgentRun` read tools (June plan Task 4 candidates) were not built; there is no way for an external worker to pick up queued runs.
6. **No always-on worker.** The agent runs only from a laptop; no Proxmox-hosted worker, no Convex→agent scheduling, no parallel weekly-brief comparison has started.
7. **No self-improvement mechanics.** Human edits are not captured into datasets, listening feedback does not flow into evals, no LangGraph memory store, no eval-gated prompt promotion, no verification sandbox.

### Corrections to the June plan

- **Codex strategy section is replaced.** The instruction "If it exposes an OpenAI-compatible `/v1/chat/completions`, use ChatOpenAI" resolved the spike question incorrectly by assumption. The confirmed integration path is `@openai/codex-sdk` (thread API over the local `codex` binary, ChatGPT-subscription OAuth from `CODEX_HOME/auth.json`). See plan `01-codex-sdk-inference-provider.md`.
- **Env var names change.** `CODEX_APP_SERVER_URL` / `CODEX_APP_SERVER_AUTH_TOKEN` / `CODEX_APP_SERVER_MODEL` are retired. New: `CODEX_HOME` (auth/session dir), `CODEX_ENABLED`, `CODEX_MODEL`, `CODEX_SANDBOX_MODE`, `CODEX_WORKDIR`. `agent/.env.example`, `agent/README.md`, and `agent/tests/codex-deep-agent.test.ts` must be updated (the test currently asserts provider selection off `CODEX_APP_SERVER_URL`).
- **Draft-write design is partially done, differently than planned.** The June plan proposed separate `hypothesisDrafts` / `recipeDrafts` tables; the implementation used a single `agentReviewDrafts` table plus a `reviewDraft` object on `agentRuns`. Keep the single-table design; extend it with a structured `payload` field rather than adding tables (plan `03`).
- **`weekly-brief-v2` graph and `source-intake-triage` graph remain unbuilt** and move to plans `04`/`05` with the sequencing gates defined in `00-master-sequence.md`.
