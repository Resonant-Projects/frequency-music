# Frequency Music feature map

Audit date: **2026-10-22**. Source baseline: `a9b728466f9254938e40761e012451b4d896825b` on `docs/feature-map`. This audit adds documentation and a verification skill; it implements no product gaps and makes no deployment or production-data claim.

The intended loop is **source → extraction/claims → correspondence/hypothesis → recipe → composition/render → listening → accumulated learning/editorial**. Intent is grounded in current schema, public APIs, route/component calls, worker/job registries, explicit stop paths and repository plans. Aspirational prose is recorded separately from shipped contracts.

> 🧠 **From Hindsight memory (Component map; Key decisions and rationale)** — The four package boundaries and existing local browser fixtures informed where to look. Current code and the dated command receipts determine every status below; historical verification/deployment claims are not reused as current proof.

## Read this map

- **done**: evidence covers the feature as scoped, including its mapped UI journey. Only offline essay reading reaches that bar in this audit.
- **partial**: some implementation/proof exists, but an intended UI seam, persistence, integration, or acceptance remains unproved or gated.
- **missing**: the named intended stage is absent, even if neighboring backend APIs exist.
- **V** = local aggregate checks/backend/worker tests; **U1–U3** = isolated fixture browsers; **B1–B4** = guarded real frontend journeys/refusal; **F1** = reproduced feedback-fixture blocker. See [commands and output](evidence/feature-map-20261022/README.md). Test passes prove their assertions, not provider quality or deployed behavior.

Each stage matrix has intent, backend status, UI exposure and entry point, happy path, edge cases, verification, status and next step. Its source table supplies linked implementation PRs/issues. The index below carries the audit PR for every feature; no gap issues were created.

## Coverage and limits

The index covers 47 feature/stage rows, all 28 registered web routes, all 41 schema tables, all public Convex export modules, all nine worker graphs, all five media job handlers and all 21 registered crons. The [surface index](feature-map/surfaces.md) records the exact mechanical inventory and its limits: an API declaration or URL does not prove a usable UI.

The safe runtime has no general isolated Convex deployment or full-app synthetic backend. Existing browser fixtures exercise selected real components/routes over injected adapters. The existing authenticated full-pipeline E2E suite uses a shared backend and was deliberately not executed. Every backend-backed feature stays partial unless the full journey has its own evidence. No production configuration, data, media, identity, or provider was queried to improve coverage.

Local evidence is dated to the source baseline above. The PR changes only audit documents/skill instructions; it does not change that application source. Source hashes, commands, output excerpts and cleanup receipts are committed; large raw logs/screenshots/traces stay in their explicitly identified local ignored locations. A reader without those files can still assess each command-result claim from committed output.

## Scope decisions preserved

Recipe loop closure is already planned but gated by eval acceptance; render validation, signers, docket preparation, tournament enablement and passage/generator follow-ons retain their documented gates. CLI-first starter kits, external ingestion and operational tools are not assumed to require new product UI. Proposed UI exposure is classified **needs-decision** when the repository does not settle it. The goal is to make current intent reviewable, not convert every internal maintenance endpoint or old aspiration into a new feature.
