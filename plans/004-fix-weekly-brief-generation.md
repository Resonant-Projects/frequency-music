## Why this matters

The weekly brief is the project's flagship output (the "weekly turn"), generated by a Friday cron and a manual action. Both paths call `generateBriefCore`, which dereferences `ctx.db` — but in Convex, **action contexts have no `db` property** (only `runQuery`/`runMutation`/`runAction`/`scheduler`/`auth`/`storage`). `ctx.db` is `undefined` at runtime, so every invocation throws `Cannot read properties of undefined (reading 'query')` before the LLM call. The bug is masked twice over: the function signature is `ctx: any`, and the unit tests inject a fake `{ db }` ctx that real actions never receive. A secondary date bug in the same function stamps Sunday-run briefs with *next* week's `weekOf`.

## Steps

### Step 1: Add an `internalQuery` that gathers all db-reads in one transaction

In `convex/weeklyBriefs.ts`, add (near the `create` internalMutation at line 66):

```ts
export const getBriefContext = internalQuery({
  args: {},
  handler: async (ctx) => {
    const recommendation = await computeRecommendedActionContext(ctx.db, { limit: 5 });
    const fallbackTheses =
      recommendation.theses.length > 0
        ? []
        : await ctx.db
            .query("theses")
            .withIndex("by_status_updatedAt", (q) => q.eq("status", "active"))
            .order("desc")
            .take(10);
    const editorialSignals = await computeEditorialSignals(ctx.db, 8);
    return { recommendation, fallbackTheses, editorialSignals };
  },
});
```

Import `internalQuery` from `./_generated/server` and `computeEditorialSignals` from `./dashboard` / `computeRecommendedActionContext` from `./campaigns` (both already imported — verify). Omit a `returns:` validator (internal-only; the repo uses validators mainly on public functions) — if the codegen complains, use `returns: v.any()`.

**Verify**: `grep -n 'getBriefContext = internalQuery' convex/weeklyBriefs.ts` → 1 match; scoped typecheck not worse.

### Step 2: Rewrite `generateBriefCore` to consume the query

- Change the signature from `ctx: any` to a minimal structural type and delete the eslint-disable:

  ```ts
  type BriefCtx = {
    runQuery: GenericActionCtx<DataModel>["runQuery"];
    runMutation: GenericActionCtx<DataModel>["runMutation"];
  };
  export async function generateBriefCore(ctx: BriefCtx, args: GenerateBriefArgs): Promise<GenerateBriefResult>
  ```

  (`GenericActionCtx` from `convex/server`, `DataModel` from `./_generated/dataModel`. If that import dance fights you, an inline structural type `{ runQuery: (ref: any, args: any) => Promise<any>; runMutation: ... }` is acceptable — the point is: **no `db` member**.)

- Replace the three `ctx.db` uses with one call at the top:

  ```ts
  const { recommendation, fallbackTheses, editorialSignals } = await ctx.runQuery(
    internal.weeklyBriefs.getBriefContext,
    {},
  );

    recommendationContext.theses.length > 0 ? recommendationContext.theses : fallbackTheses;
  ```

  Keep every downstream use (`recommendationContext.hypotheses`, `.recipes`, `.actions`, `.failureArchive`, `.campaign`, `editorialSignals`) exactly as it is today.

**Verify**: `grep -n 'ctx\.db' convex/weeklyBriefs.ts` → no matches; `bun run test` → existing weeklyBriefs tests now FAIL (expected — they inject `{ db }`; fixed in Step 4).

### Step 3: Fix the Monday/`weekOf` computation (UTC, Sunday-correct)

Replace lines 300-303 with:

```ts
const now = new Date();
const monday = new Date(now);
const daysSinceMonday = (now.getUTCDay() + 6) % 7; // Mon=0 ... Sun=6
monday.setUTCDate(now.getUTCDate() - daysSinceMonday);
const weekOf = monday.toISOString().split("T")[0] as string;
```

**Verify**: temporary check `bun -e 'const now=new Date("2026-06-14T12:00:00Z"); const m=new Date(now); m.setUTCDate(now.getUTCDate()-((now.getUTCDay()+6)%7)); console.log(m.toISOString().split("T")[0])'` → `2026-06-08` (the *current* week's Monday for a Sunday input).
