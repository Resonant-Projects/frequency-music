## Why this matters

Root `package.json` carries four dependencies with **zero imports anywhere**
(verified by repo-wide grep at `a30f10c`): two duplicate-purpose PDF parsers,
`playwright` (all browser automation actually goes through `@onkernel/sdk`'s
cloud API), and `youtube-transcript` (the script shells out to the Fabric CLI
instead). They mislead readers about how fetching actually works and widen the
install/audit surface. Separately, `agent/` contains BOTH `bun.lock` (64KB)
and an npm `package-lock.json` (148KB) — in a Bun monorepo, that invites
divergent installs. And two linters (biome + oxlint) run over the same
TypeScript with no documented division of labor.

### Step 2: Remove them and reinstall

Delete the four lines from root `package.json` dependencies, then `bun install`.

**Verify**: `bun install` → exit 0.
**Verify**: `grep -c "pdf-parse\|pdf-parser-client-side\|\"playwright\"\|youtube-transcript" package.json` → 0.
**Verify**: `bun test convex/*.test.ts` → all pass; `bunx tsc --noEmit -p tsconfig.json` → exit 0.

### Step 3: Standardize `agent/` on bun

1. `git rm agent/package-lock.json`
2. In `agent/package.json`, add `"packageManager": "bun@1.3.14"` (mirroring
   web's pattern; 1.3.14 is the bun that generated the current root lock —
   check `bun --version` and use the installed version if different).
3. `cd agent && bun install`

**Verify**: `ls agent/package-lock.json` → No such file.
**Verify**: `cd agent && bun run verify && bun test` → exit 0.

### Step 4: Document the linter split

Add to `CLAUDE.md`'s "Bun Defaults" section (or an adjacent tooling section),
four lines:

```md
## Lint & format
- **biome** = formatter (`bun run format`); its linter config exists but oxlint is the primary linter.
- **oxlint** = linter (`bun run lint`, check-only: `bun run lint:check` if present).
- Don't add overlapping rules to both configs; oxlint wins for lint rules.
```

**Verify**: `grep -n "oxlint wins" CLAUDE.md` → 1 hit.

### Step 5: Full check

**Verify**: `git status --short` → only the five in-scope files (package.json,
bun.lock, agent/package.json, deleted agent/package-lock.json, CLAUDE.md, plus
possibly agent/bun.lock regenerated).
